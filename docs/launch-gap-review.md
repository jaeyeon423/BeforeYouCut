# 미용사 출시 갭 리뷰

Last updated: 2026-06-19

## 기준

무신사는 대규모 패션 플랫폼이다. 공개 자료 기준으로 추천판, 개인화 추천, 랭킹, 검색어/브랜드 랭킹, 스냅, 이벤트, 카테고리 큐레이션을 주요 쇼핑 장치로 운영한다.

참고:

- 무신사 추천판: https://newsroom.musinsa.com/newsroom-menu/2021-1117-03
- 무신사 랭킹: https://newsroom.musinsa.com/newsroom-menu/2021-1007-03
- 무신사 소개: https://about.musinsa.com/newsroom/about-musinsa

미용사는 초기부터 무신사식 커뮤니티/랭킹/혜택을 흉내 내기보다, 미용 전문가가 도구를 믿고 살 수 있는 거래 구조를 먼저 완성한다.

## 이번 정리로 반영된 것

- 서비스명과 메타데이터를 `미용사`/`MIYONGSA`로 1차 전환.
- 공개 푸터에서 가짜 사업자명, 대표자명, 사업자번호를 노출하지 않도록 제거.
- 판매자 센터에서 상품을 직접 추가할 수 있는 서버 액션과 UI 추가.
- 새 상품 등록 시 상품명, 가격, 카테고리, 설명, 소재, 제조국, 치수, 취급 주의, KC 인증 여부를 함께 받도록 변경.
- `src/data/data.js`의 미사용 샘플 셀러/상품/랭킹/인기검색어 데이터를 제거하고, 런타임에 필요한 카테고리/아이콘/가격 포맷만 남김.
- 판매자 입점 시 불완전한 첫 상품을 자동 생성하지 않도록 변경.
- 공개 홈, 카테고리, 상품 상세, 브랜드 목록은 활성 판매자와 그 상품만 노출하도록 변경.
- 상품 이미지 배열을 DB에 추가하고, 홈 카드·랭킹·장바구니·주문 내역·상품 상세에 실제 이미지가 표시되도록 변경.
- 판매자 센터에서 상품 이미지 파일 업로드 또는 공개 이미지 URL 입력이 가능하도록 변경.
- 기존 seed 상품에 카테고리별 제품 이미지 자산을 연결.
- 신규 상품은 관리자 승인 전까지 공개 노출되지 않도록 `reviewStatus` 검수 상태를 추가.
- `/admin` 운영 콘솔을 추가해 판매자 승인/숨김, 상품 승인/반려/숨김, 주문 상태 변경, 환불 처리, 정산 상태 처리, CS 답변을 처리.
- 주문 생성 시 서버 기준 상품 가격과 공개 상태를 검증하고, 주문 항목별 정산 레코드를 같은 트랜잭션에서 생성하도록 변경.
- `/orders/[id]` 주문 상세 화면을 추가해 구매자는 배송/반품 상태 확인 및 반품·환불 신청을, 판매자와 관리자는 송장 등록을 할 수 있도록 연결.
- 마이페이지 주문 내역, 결제 완료 후 이동, 판매자 센터 최근 주문, 관리자 주문 카드에서 주문 상세 화면으로 이동하도록 연결.
- 판매자 센터에 사업자/KYC 정보, 문서 URL, 정산 계좌 제출 UI를 추가하고 계좌번호는 AES-256-CBC 암호화 저장하도록 변경.
- 관리자 콘솔에서 판매자 KYC 누락 항목, 제출 문서, 정산 계좌 검증 여부를 확인하고 KYC 승인/반려를 처리하도록 변경.
- Supabase placeholder URL/key fallback과 `user_default` 게스트 계정 재생성 로직을 제거.
- 판매자 서류를 비공개 `seller-documents` 버킷에 업로드하고, 판매자/관리자 화면에서는 서버가 발급한 짧은 서명 URL로 열람하도록 변경.
- 주문 상태가 `구매확정`으로 바뀌면 정산이 지급 대기로 확정되고, `취소`/`환불완료` 주문은 미지급 정산에서 제외되며, 관리자가 확정 정산을 지급 완료로 기록할 수 있도록 변경.
- 상품/브랜드 문의가 실제 `CsInquiry`로 접수되도록 변경하고, 관리자 콘솔에서 문의 답변 저장·처리중 전환·종료 처리와 환불 승인/거절/완료 기록을 할 수 있도록 변경.
- 결제 전 주문이 생성되던 임시 흐름을 제거하고, 토스페이먼츠 V2 결제창 요청 전 `Payment` 세션을 저장한 뒤 서버 승인 성공 시에만 주문·정산을 생성하도록 변경.
- `prisma/rls.sql`에 `product-images` 공개 버킷과 `seller-documents` 비공개 버킷/Storage 정책 SQL을 추가.

## 무신사 대비 부족한 점

현재 부족하지만, 바로 따라 만들 필요가 없는 것:

- 개인화 추천판: 현재는 사용자 행동 데이터가 충분하지 않아 품질 있는 추천을 만들기 어렵다.
- 실시간/기간별 랭킹: 무신사는 매출, 판매 수량, 조회 수, 후기 수 등을 반영한다고 공개한다. 미용사는 거래량이 쌓이기 전까지 실시간 랭킹을 강조하면 신뢰도가 떨어진다.
- 검색어/브랜드 랭킹: 실제 검색 로그와 브랜드 트래픽이 생긴 뒤 도입해야 한다.
- 스냅/커뮤니티: 미용 도구 마켓의 초기 구매 전환에는 상품 스펙, 판매자 검수, 배송/반품 신뢰가 더 중요하다.
- 대규모 이벤트/쿠폰/적립금: PG, 주문, 정산, 환불이 안정화된 뒤 붙인다.

출시 전에 반드시 채워야 하는 것:

- 토스페이먼츠 실제 테스트/라이브 키 등록, 결제 성공/실패 운영 검증, 웹훅 처리.
- Supabase `product-images` 버킷 생성 여부와 공개 읽기/RLS 정책의 프로덕션 검증.
- Supabase `seller-documents` 비공개 버킷/Storage 정책의 실제 운영 프로젝트 적용과 열람 권한 검증.
- 실제 PG 환불 API 실행, 은행 이체 또는 정산 API 지급 실행.
- 택배사 실시간 배송 추적 API 연동과 배송완료 자동 반영.
- 정산 계좌 실명/1원 인증, 은행 이체/정산 API 연동.
- 실제 사업자 정보, 통신판매업 신고번호, 고객센터, 개인정보보호책임자, 도메인 확정.
- Supabase RLS와 Storage 정책의 프로덕션 검증.

## 우선순위

1. Supabase Storage `product-images` 버킷과 운영 정책 검증.
2. 토스페이먼츠 테스트/라이브 키 등록과 결제 운영 검증.
3. Supabase Storage 정책 SQL 운영 적용과 열람 권한 검증.
4. 실제 PG 환불 실행과 정산 이체/API 연동.
5. 택배사 배송 추적 API와 배송완료 자동 처리.
6. 실제 사업자/도메인/약관 시행일 반영.
7. 검색 필터와 카테고리 품질 개선.
8. 실제 데이터가 쌓인 뒤 랭킹/추천/후기 도입.
