# BEFORE YOU CUT 오픈마켓 구축 체크리스트

원문 문서: `docs/hair-beauty-open-market-guide.docx`

이 체크리스트는 헤어/미용용품 입점형 오픈마켓을 실제 출시하기 위해 필요한 일을 `AI가 구축하거나 초안화할 수 있는 부분`과 `사람이 직접 처리해야 하는 부분`으로 나눈 실행 목록입니다. 법무, 세무, 인허가 판단은 최종적으로 전문가 또는 관할 기관 확인이 필요합니다.

## 1. AI가 구축해줄 수 있는 부분

### 서비스 기능과 화면

- [ ] 구매자 홈, 카테고리, 검색, 상품 상세, 셀러 상세 화면을 운영 데이터 기준으로 정리한다.
- [ ] 찜, 셀러 팔로우, 장바구니, 주문 생성 흐름을 로그인 사용자 기준으로 안정화한다.
- [ ] 비로그인 사용자의 쓰기 동작에는 로그인 유도 UI를 붙인다.
- [ ] 모바일 우선 UI에서 하단 내비게이션, 상품 카드, 필터, 정렬, 빈 상태, 오류 상태를 정리한다.
- [ ] 상품정보제공고시 항목이 상품 상세에 빠짐없이 표시되도록 상품 모델과 UI를 확장한다.
- [ ] 통신판매중개자 고지 문구와 사업자 정보가 푸터와 약관 화면에 노출되도록 구성한다.

### 셀러 입점과 심사 시스템

- [ ] 사업자 셀러와 비사업자 셀러의 입점 신청 폼을 분리하거나 조건부 필드로 구성한다.
- [ ] 사업자등록증, 통신판매업 신고증, 정산 계좌, KC 인증서 등 서류 업로드 필드를 만든다.
- [ ] 비사업자 셀러의 신분 확인 서류, 정산 계좌, 월 200만 원 한도 안내를 폼에 반영한다.
- [ ] 셀러 상태값을 `신청`, `심사중`, `보완요청`, `승인`, `반려`, `정지` 등으로 관리한다.
- [ ] 관리자 화면에서 셀러 신청 목록, 상세 검토, 승인/반려, 보완 요청을 처리할 수 있게 만든다.
- [ ] 셀러 약관 동의 이력, 개인정보 수집 동의 이력, 변경 시 재동의 흐름을 저장한다.

### 상품 등록과 규제 입력 통제

- [ ] 상품 등록 폼에 소재, 제조국, 치수, 취급 주의, A/S 책임자 등 고시 항목을 필수화한다.
- [ ] 품목별 KC 인증 대상 여부를 셀러가 표시하고, 대상이면 인증서 또는 인증번호를 제출하도록 만든다.
- [ ] KC 인증 자료가 필요한 상품은 관리자 승인 전까지 판매 노출을 막는다.
- [ ] 금지 품목, 허위 정보, 누락 정보에 대한 관리자 검수 상태를 둔다.
- [ ] 상품 수정 시 재심사가 필요한 필드를 정의하고, 변경 이력을 남긴다.

### 결제, 주문, 정산 보조 기능

- [ ] 토스페이먼츠 또는 선택한 PG의 결제창 연동 코드를 구현한다.
- [ ] 결제 승인, 실패, 취소, 환불, 웹훅 처리 로직을 만든다.
- [ ] 주문 상태를 `결제대기`, `결제완료`, `배송준비`, `배송중`, `구매확정`, `취소`, `환불` 등으로 관리한다.
- [ ] 운영 수수료율, 정산 주기, 자동 구매확정 기간을 설정값으로 분리한다.
- [ ] 셀러별 매출, 수수료, 환불 차감, 정산 예정액을 계산하는 정산 원장을 만든다.
- [ ] 지급대행 서비스의 실제 지급 요청 API 또는 관리자 수동 지급 내역을 연결할 수 있는 구조를 만든다.
- [ ] 비사업자 월 200만 원 결제/정산 한도 초과를 감지하는 알림 또는 제한 로직을 만든다.

### 약관, 정책, 문서 초안

- [ ] 소비자 이용약관 초안을 서비스 화면에 맞게 정리한다.
- [ ] 판매자 입점약관 초안을 수수료, 정산 주기, 책임 분담, 금지 행위 중심으로 정리한다.
- [ ] 개인정보처리방침 초안을 실제 수집 항목, 보관 기간, 위탁 업체 기준으로 정리한다.
- [ ] 청약철회, 반품, 교환, 환불 정책 초안을 상품 유형과 위생 예외 기준에 맞게 정리한다.
- [ ] 셀러 입점 안내서, 상품 등록 가이드, KC/상품정보 입력 가이드를 만든다.
- [ ] 고객센터 FAQ, 분쟁 접수 양식, 반품/교환 처리 템플릿을 만든다.

### 운영 관리자 기능

- [ ] 관리자 대시보드에 주문, 셀러, 상품, 정산, 문의/분쟁 메뉴를 만든다.
- [ ] 소비자 분쟁 접수, 처리 상태, 담당자 메모, 결과 통지를 관리한다.
- [ ] 셀러별 상품, 주문, 정산, CS 이력을 한 화면에서 볼 수 있게 만든다.
- [ ] 사업자 정보와 약관 시행일을 `site.config` 또는 관리자 설정에서 관리할 수 있게 한다.
- [ ] 서비스 공지, 약관 개정 공지, 판매자 공지 기능을 만든다.

### 보안, 데이터, 배포

- [ ] Supabase Auth 기준으로 구매자, 셀러, 관리자 권한을 분리한다.
- [ ] 서버 액션에서 클라이언트가 보낸 사용자 ID를 신뢰하지 않고 세션 기준으로 처리한다.
- [ ] 계좌번호, 신분 확인 자료 등 민감 정보는 서버 전용 저장소와 암호화 전략을 적용한다.
- [ ] Supabase RLS, 파일 접근 권한, 관리자 권한 검증을 점검한다.
- [ ] Sentry 에러 수집, 운영 로그, 결제 웹훅 실패 재처리 로그를 붙인다.
- [ ] Vercel 환경변수, Supabase 환경변수, PG 키를 배포 환경별로 분리한다.
- [ ] 주문, 결제, 환불, 정산, 셀러 승인에 대한 테스트를 추가한다.

## 2. 사람이 직접 해야 하는 부분

### 사업자와 신고

- [ ] 개인사업자 또는 법인 설립 여부를 결정한다.
- [ ] 사업자등록을 진행하고 업종에 전자상거래 소매업과 통신판매중개업 관련 업종을 반영한다.
- [ ] 사업장 주소, 대표자, 법인 등기, 인감 등 사업자 서류를 준비한다.
- [ ] 도메인을 확정하고 실제 서비스 URL을 준비한다.
- [ ] 구매안전서비스 이용확인증을 확보한 뒤 통신판매업 신고를 진행한다.
- [ ] 통신판매업 신고증 수령 후 등록면허세 납부 여부를 확인한다.

### PG와 지급대행 계약

- [ ] 토스페이먼츠 또는 다른 PG사의 지급대행 서비스 사용 여부를 결정한다.
- [ ] PG사에 대표가맹점/고객사 계약을 신청한다.
- [ ] 사업자등록증, 통신판매업 신고증, 도메인 증빙, 법인등기부등본, 법인인감증명서, 주주명부 등 계약 서류를 제출한다.
- [ ] PG 심사 결과, 수수료, 정산 주기, 보증보험료, 가입비, 연관리비를 확인한다.
- [ ] PG 상점관리자에서 셀러 등록, KYC, 지급 요청, 잔액 관리 절차를 실제로 운영한다.
- [ ] PG에서 발급되는 가맹점 ID, 클라이언트 키, 시크릿 키를 안전하게 전달한다.

### 법무, 세무, 개인정보

- [ ] 소비자 이용약관을 전자상거래 전문 변호사에게 검토받는다.
- [ ] 판매자 입점약관을 수수료, 정산, 책임 분담, 금지 행위 기준으로 검토받는다.
- [ ] 개인정보처리방침과 개인정보 수집/이용 동의 문구를 검토받는다.
- [ ] 청약철회, 반품, 교환 예외 사유가 전자상거래법상 허용되는지 확인한다.
- [ ] 개인정보 보호책임자 지정 여부와 처리 위탁 계약 범위를 정한다.
- [ ] 사업자 셀러 세금계산서, 비사업자 셀러 원천징수 여부를 세무사에게 확인한다.
- [ ] 운영사 부가세 신고와 정산 자료 보관 방식에 대해 세무 처리 기준을 확정한다.
- [ ] 적립금, 포인트, 충전금 기능을 도입할 경우 선불전자지급수단 발행업 등록 필요 여부를 검토한다.

### 판매자와 상품 검증

- [ ] 사업자 셀러의 사업자등록증과 통신판매업 신고증 진위 여부를 확인한다.
- [ ] 비사업자 셀러의 신분 확인 기준과 보관 범위를 확정한다.
- [ ] 판매자별 정산 계좌 명의와 신청자 정보 일치 여부를 확인한다.
- [ ] 취급 품목별 KC 인증 또는 전안법 대상 여부를 전문가, 시험기관, 관할 기관 기준으로 확인한다.
- [ ] 상품정보제공고시에 들어가는 소재, 제조국, 치수, 취급 주의, A/S 책임자 정보가 실제 상품과 맞는지 검수한다.
- [ ] 허위 상품, 병행수입, 중고/리퍼브, 주문제작 상품 허용 여부를 운영 정책으로 확정한다.

### 운영과 고객 응대

- [ ] 고객센터 전화번호, 이메일, 운영 시간, 응대 담당자를 정한다.
- [ ] 분쟁 발생 시 소비자, 셀러, 운영사의 책임 범위와 처리 절차를 확정한다.
- [ ] 환불, 반품, 교환에 따른 배송비 부담 기준을 확정한다.
- [ ] 입점 수수료율, 정산 주기, 구매확정 기간, 보류금 정책을 확정한다.
- [ ] 셀러 교육 자료와 입점 심사 담당자를 정한다.
- [ ] 서비스명과 로고의 상표 출원 여부를 결정한다.
- [ ] 출시 전 실제 결제, 취소, 환불, 정산, CS 시나리오를 사람이 직접 검수한다.

## 3. AI가 준비하고 사람이 승인해야 하는 부분

- [ ] AI가 약관과 개인정보처리방침 초안을 만들고, 사람과 전문가가 최종 승인한다.
- [ ] AI가 입점 계약서 구조를 만들고, 수수료/정산/책임 범위는 운영자가 확정한다.
- [ ] AI가 상품 등록 필드를 강제하도록 구현하고, KC 대상 여부 판단은 사람 또는 전문가가 확인한다.
- [ ] AI가 결제/정산 계산 로직을 만들고, PG 계약 조건과 세무 기준은 사람이 입력한다.
- [ ] AI가 관리자 검수 화면을 만들고, 실제 서류 진위 확인은 운영자가 수행한다.
- [ ] AI가 CS 템플릿을 만들고, 실제 소비자 분쟁 판단과 보상 결정은 운영자가 수행한다.
- [ ] AI가 배포와 모니터링 설정을 도와주고, 비밀키 발급과 운영 계정 권한 관리는 사람이 한다.

## 4. 권장 진행 순서

1. [ ] 운영자가 사업자 형태, 셀러 유형, 수수료율, 정산 주기, 환불 정책을 먼저 확정한다.
2. [ ] AI가 `site.config`, 약관 페이지, 판매자 입점 폼, 상품 고시 필드를 운영 정책에 맞춰 반영한다.
3. [ ] 운영자가 사업자등록과 PG 지급대행 계약을 진행한다.
4. [ ] AI가 PG 키를 받은 뒤 결제 승인, 웹훅, 주문 상태, 환불 흐름을 구현한다.
5. [ ] 운영자가 구매안전서비스 이용확인증으로 통신판매업 신고를 완료한다.
6. [ ] AI가 관리자 셀러 심사, 상품 검수, 정산 원장, CS 기능을 보강한다.
7. [ ] 변호사와 세무사가 약관, 개인정보, 정산, 세무 처리를 검토한다.
8. [ ] 운영자가 실제 셀러 1~3명으로 입점, 상품 등록, 결제, 취소, 환불, 정산 리허설을 진행한다.
9. [ ] AI가 리허설에서 발견된 오류와 UX 문제를 수정한다.
10. [ ] 운영자가 최종 법적 표시 정보, 고객센터 정보, 신고번호, PG 상태를 확인한 뒤 출시한다.

## 5. 초기 출시에서 피하는 것이 좋은 기능

- [ ] 적립금, 포인트, 충전금처럼 전자금융업 검토가 커지는 기능은 초기 출시 범위에서 제외한다.
- [ ] 운영자가 직접 판매자가 되는 직매입/위탁판매 모델은 중개 모델과 책임 구조가 달라지므로 별도 검토 전까지 제외한다.
- [ ] 해외 판매, 해외 배송, 해외 셀러 입점은 세금, 통관, 소비자보호 범위가 커지므로 초기에는 제외한다.
- [ ] 의료기기, 화장품, 전기용품 등 별도 인허가 가능성이 큰 품목은 검토 전까지 입점을 제한한다.
